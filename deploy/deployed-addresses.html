Purpose of this page

This page is the canonical reference for “What is deployed?” Each entry follows a claim → evidence → verification structure so that readers can independently validate deployed components.

The public site is intended to reflect the project’s documented verification model: the live site, this deployment inventory, and supporting evidence (explorers, registry digests, source repo, receipts) are aligned so reviewers can inspect what is deployed and follow the evidence without that being interpreted as an announcement of economic activation. Minting, liquidity, and related features remain subject to separate authorization—and are currently intentionally disabled.

What a reviewer can do here:

  1. Understand the architecture — linked overview & docs
  2. See what is actually deployed — inventory entries below
  3. Inspect supporting evidence — explorers, registry, txs, receipts
  4. Reproduce or verify findings — verification portal & builder path
  5. Read operational & governance status — what is enabled vs what decisions remain

Keep these states separate:

State Meaning
Technical What exists and can be verified (addresses, bytecode, explorers)
Operational What is currently enabled (mint/liquidity disabled by design)
Governance What decisions remain before any economic functionality is authorized

Communication principles

  • Process over conclusion. Show how results are obtained (claim → evidence → verification) instead of asking readers to accept them.
  • Observables over narrative. Prefer deployed artifacts, repository history, transactions, and reproducible evidence over descriptive claims.
  • Deployment inventory is not economic readiness. Publishing what is deployed is distinct from authorizing economic functionality. A deployment inventory is not an economic activation announcement.

Technical state (what exists) · operational state (what is enabled) · governance state (what is authorized) remain separate.
