# Public Review Boundary

Quantum Pi Forge contains executable, philosophical, experimental, and future-facing layers.

For public review, this document separates what can be locally verified from what is contextual, disabled, experimental, or aspirational.

The review standard is simple:

> Do not rely on the mythology first.
> Run the evidence path first.

---

## Review Scope

Public review should begin with the smallest reproducible core:

1. repository evidence index;
2. claim map;
3. static review boundary;
4. evidence snapshot receipt;
5. local verification commands;
6. authority boundaries around wallet, minting, posting, governance, deployment, and chain mutation.

The broader OINIO, Canon, Sacred Trinity, soul-system, resonance, and philosophical language is context. It is not a substitute for executable evidence.

---

## Verified / Locally Reviewable

The following surfaces are intended to be reviewed through local repository checks:

- evidence index verification;
- claim map drift checks;
- static review boundary checks;
- evidence snapshot receipt verification;
- reviewer-facing documentation paths;
- local-only Hermes/Ollama documentation where present;
- no-mutation authority boundaries where explicitly encoded.

Reviewers should prefer local commands and committed evidence files over narrative claims.

---

## Non-Executing / Disabled Unless Explicitly Authorized

The following are not active production authority merely because related files, docs, or UI surfaces exist:

- staking execution;
- wallet signing;
- minting;
- fund movement;
- token transfer;
- ownership transfer;
- governance execution;
- autonomous posting;
- deployment authority;
- live chain mutation.

Any future activation of these surfaces requires a separate, explicit, reviewable authorization path.

---

## Experimental / Aspirational

The following should be treated as experimental, philosophical, simulated, metaphorical, or future-facing unless paired with a specific proof artifact:

- collective consciousness metrics;
- quantum-inspired framing;
- autonomous multi-agent operation beyond bounded local scripts;
- Pi Network integration claims;
- production-grade bridge claims;
- self-sustaining economic claims;
- large-scale community adoption claims;
- post-quantum security claims beyond concrete implementation evidence.

These concepts may be part of the project vision, but they are not evidence by themselves.

---

## Philosophical Context

OINIO, the Canon, Sacred Trinity Architecture, resonance language, and soul-system framing describe the project's values and symbolic architecture.

They should be read as philosophical context unless a given claim is linked to:

- a committed file;
- a verifier;
- a receipt;
- a test;
- a manifest;
- a reproducible command;
- an on-chain transaction or independently inspectable artifact.

---

## Reviewer Path

A reviewer should be able to begin without accepting any philosophical premise.

Recommended local checks:

- npm run verify:evidence
- npm run claim-map:check
- npm run review:static-boundary

If a command is unavailable, failing, renamed, or intentionally omitted, that should be recorded as a review finding rather than hidden behind narrative explanation.

---

## Public Claim Rule

Any public claim should fit one of these categories:

| Category | Meaning |
|---|---|
| Verified | Reproducible by local command, committed artifact, or independent source |
| Partial | Some evidence exists, but scope is limited |
| Disabled | Surface exists but execution is intentionally inactive |
| Experimental | Prototype, simulation, research, or non-production feature |
| Philosophical | Values, metaphor, governance language, or symbolic framing |
| Future | Intended direction, not current state |

Claims that do not fit one of these categories should not be presented as current operational facts.

---

## Plain-Language Summary

Quantum Pi Forge should be reviewed as an evidence-first project.

The philosophical layer explains why it exists.

The repository evidence path proves what currently exists.

The distinction matters.
