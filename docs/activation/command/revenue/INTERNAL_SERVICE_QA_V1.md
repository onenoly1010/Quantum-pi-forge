# Internal Service QA v1

**Purpose:** Try to disprove every service claim before it becomes a proposal or
delivery commitment.

| Claim | Challenge | Current answer | Remediation task |
| --- | --- | --- | --- |
| QPF can perform evidence-readiness work. | Is it proven beyond QPF's own repository? | Internal evidence methods exist; third-party delivery is not yet demonstrated. | Require discovery and label external adaptation as an assumption. |
| QPF can produce deployment transparency packages. | Can it access/verify every client environment? | No; only public or client-approved references can be assessed. | Include environment-access exclusions in each scope. |
| QPF offers sovereign-AI review. | Is there a qualified buyer and portable delivery method? | No current qualified opportunity. | Keep capability on watchlist until a named need is evidenced. |
| QPF can improve developer onboarding. | Is there a qualified buyer and defined deliverable? | No current qualified opportunity. | Keep capability on watchlist until a named need is evidenced. |
| QPF has commercial track record. | Is a completed paid third-party engagement evidenced? | No. | Use an honest first-engagement disclosure; do not imply clients. |
| QPF can quote delivery. | Are effort and price inputs defined? | No; human-owned decision required. | Add internal effort bands only after a human reviews capacity. |

## Open remediation tasks

1. Reconcile all evidence-readiness offer documents into one canonical scope.
2. Add offer-specific acceptance criteria and client-input checklists.
3. Add a human-owned internal effort-sizing framework; do not publish pricing
   without approval.
4. Obtain a named, evidence-backed customer need before outreach.
5. Create a first-engagement closeout receipt template after a real engagement
   is authorized.
