# Service Delivery Playbooks v1

**Status:** Internal preparation only. Human authorization is required before
any external communication, proposal, agreement, or delivery commitment.

## Service A - Evidence-readiness walkthrough

| Item | Procedure |
| --- | --- |
| Client prerequisites | Human-approved contact; bounded public or client-supplied artifact set; written problem statement; no secrets or private keys. |
| Timeline | Human-owned after discovery; no duration promise is made in advance. |
| Deliverables | Claim-to-evidence map, reproducible-check record where feasible, evidence-gap/risk list, and prioritized next-action brief. |
| Acceptance criteria | Artifact inventory is complete; each reviewed claim is labeled evidenced, unverified, or excluded; findings and limitations are written. |
| Evidence package | Source links, command/output references where appropriate, deployment/public references, and stated assumptions. |
| Completion checklist | Scope confirmed; inputs inventoried; findings reviewed; exclusions recorded; delivery receipt prepared. |
| Post-delivery report | Problem, scope, methods, evidence reviewed, findings, exclusions, client decisions required, and follow-up recommendation. |

**Not included:** Legal advice, audit certification, funding approval, wallet access,
private-key handling, token work, or a promise that client systems can be
verified without discovery.

## Service B - Deployment transparency baseline

| Item | Procedure |
| --- | --- |
| Client prerequisites | Human-approved contact; public deployment URL or client-approved environment reference; source/release references; no credentials. |
| Timeline | Human-owned after discovery; no duration promise is made in advance. |
| Deliverables | Deployment/source inventory, public-safe verification path, conflict/missing-link list, and transparency baseline report. |
| Acceptance criteria | Current endpoint and source references are identified; known conflicts are written; verification steps and limitations are documented. |
| Evidence package | Release/source references, deployment metadata, public endpoint checks, and reproducible verification instructions where available. |
| Completion checklist | Scope confirmed; references collected; public-safe report reviewed; unresolved gaps assigned; delivery receipt prepared. |
| Post-delivery report | Scope, observed deployment state, source mapping, unresolved evidence gaps, verification instructions, and next action. |

**Not included:** Production deployment, credential access, infrastructure changes,
security certification, or a promise that all client environments can be
independently verified.

## Playbook use gate

Use either playbook only after the commercial-readiness gate confirms a named
need, a human-approved recipient, a bounded scope, acceptance checks, and a
human-owned price/effort decision.
