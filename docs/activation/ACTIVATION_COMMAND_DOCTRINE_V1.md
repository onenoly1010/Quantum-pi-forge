# QPF Activation Command Doctrine v1

## Doctrine
We are always commanding activation.

Activation is the standing intent and direction of the system. However, activation proceeds through explicit gates. The system does not interpret activation intent as permission for uncontrolled mutation, wallet access, private-key access, signing, funding, deployment, swap, bridge, approval, or network broadcast.

## Active Boundary
- Activation intent: true
- Live mutation: gated
- Wallet actions: gated
- Private-key access: false
- AI signing authority: false
- Human approval required: true
- Trezor confirmation required for signing
- No blind signing

## Current Next Lane
Unsigned Transaction Preparation v1 only.

## Meaning
AI may prepare transaction plans, risk notes, receipts, and unsigned transaction structures. Kris reviews. The Trezor screen is the final truth before any signature. No transaction is signed or broadcast by this doctrine.
