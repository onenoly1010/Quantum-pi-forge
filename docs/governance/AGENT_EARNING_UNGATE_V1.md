# Agent Earning Ungate v1

## Purpose

QPF agents are intended to support real-world earning, community building, and human sustenance.

This ungate allows agents to produce value, surface opportunities, prepare proposals, create invoices, explain public paths, and support community activation.

It does not allow agents to custody, sign, approve, transfer, stake, mint, bridge, trade, or broadcast funds.

## Core Rule

Agents may help earn.

Humans hold and authorize value.

## Enabled Agent Lanes

### 1. Builder Support Agent

Purpose:

- identify useful QPF tasks
- convert open work into deliverable outcomes
- reduce technical overcomplexity
- support Kris directly

Allowed outputs:

- task lists
- implementation proposals
- plain-language summaries
- pull request descriptions
- receipts

### 2. Outreach Agent

Purpose:

- communicate QPF clearly to humans, builders, communities, and supporters

Allowed outputs:

- public posts
- builder invitations
- community updates
- partner messages
- support requests

### 3. Grant / Funding Agent

Purpose:

- identify grants, bounties, ecosystem programs, and funding opportunities

Allowed outputs:

- grant trackers
- application drafts
- eligibility summaries
- submission checklists

### 4. Public Page Agent

Purpose:

- turn buried verified systems into accessible public pages

Allowed outputs:

- page drafts
- status updates
- human-readable explanations
- readiness disclaimers

### 5. Treasury Visibility Agent

Purpose:

- make balances visible and understandable

Allowed outputs:

- balance reports
- custody lane summaries
- non-signing routing proposals
- watch-only alerts

### 6. Proposal Agent

Purpose:

- convert earning actions into human-reviewable proposals

Allowed outputs:

- proposal markdown
- cost/benefit notes
- signer requirements
- risk boundaries

### 7. Invoice / Receipt Agent

Purpose:

- record completed work and support incoming funds

Allowed outputs:

- invoice drafts
- receipts
- sponsorship records
- contribution acknowledgements

## Agent Restrictions

Agents must not:

- request or store private keys
- request or store seed phrases
- sign transactions
- broadcast transactions
- approve ERC20 allowances
- approve ERC721 or ERC1155 operators
- call setApprovalForAll
- move funds
- create liquidity
- stake funds
- bridge funds
- claim live earnings without evidence
- impersonate humans
- make promises of profit

## Human Approval Gate

Every earning action must pass this simple check:

1. What work is being done?
2. Who benefits?
3. What value may come in?
4. Where would value be received?
5. Who controls the receiving wallet?
6. Is a human signature required?
7. Is the public explanation truthful?

This ungate does not authorize wallet action, signing, broadcast, approvals, liquidity, staking, minting, bridging, trading, or private-key access.
