# QPF Canonical Strategy v1

**Status:** Internal policy / strategy canon

**Scope:** Constellation roles, product boundary, economic model, governance boundaries, and sequencing. This document does not authorize implementation, deployment, economic activation, or partnership outreach.

## 1. Purpose

Quantum Pi Forge (QPF) is the canonical trust and verification layer for verifiable AI agents and digital systems. This strategy establishes one internal reference for how the constellation fits together and how trust, utility, and economics remain separate.

## 2. Constellation roles

| Component | Canonical role |
| --- | --- |
| **QPF** | Trust, identity, evidence, provenance, canonicalization, verification, receipts, and public inspection. |
| **OINIO** | Agent soul/local identity, persistent context, and sovereign/local-first agent layer. |
| **INFT agents** | Identifiable economic actors/containers built on verified identity and evidence. |
| **0G** | Primary decentralized AI infrastructure and ecosystem opportunity. |
| **Model providers** | Integration and ecosystem partners; not the economic foundation of QPF. |
| **Pi** | Potential payment/ecosystem rail; not the current QPF business model. |

## 3. Product boundary

### 3.1 Protocol trust layer — free

QPF does not charge people merely to establish verifiable truth. The protocol trust layer includes, as applicable:

- identity;
- canonicalization;
- evidence;
- provenance;
- verification;
- receipts;
- evidence binding;
- public inspection.

### 3.2 Optional professional services — paid for labor

Paid services may exist around the protocol where they represent human or operational labor rather than a toll on protocol truth. Examples include integration, consulting, onboarding, custom packaging, support, and defined service-level commitments.

These services must not make ordinary protocol verification pay-to-enter.

### 3.3 Future protocol participation — not yet designed or authorized

The long-term economic model is participation in **defined economic events generated by verified agent activity**. This does not mean a fee for merely being an agent, and it does not establish a percentage, settlement mechanism, token entitlement, or contract behavior.

The economic mechanism remains intentionally undecided until real agent utility and real economic activity exist.

## 4. Strategic flywheel

```text
TRUST
  -> IDENTIFIABLE AGENT
  -> UTILITY
  -> REAL ECONOMIC ACTIVITY
  -> QPF PARTICIPATION
```

The intended model is not:

```text
PAY -> RECEIVE TRUST
```

## 5. Hard boundaries

The following invariants apply across the constellation:

- Verification establishes trust; it does not authorize economics.
- Verification is not payment.
- Verification is not ownership.
- Verification is not authorization.
- Passing verification does not imply approval, deployment, Genesis activation, minting, liquidity, staking, wallet action, or economic activation.
- Prepared, verified, approved, and executed are distinct states.
- Existing QPF verification and evidence machinery is preferred over duplicate verifiers, duplicate evidence ledgers, or parallel lineage engines.
- Identity semantics must not be silently changed as part of unrelated economic or partnership work.

## 6. Current technical sequence

The identity trust sequence is:

```text
A: identity schema/spec
  -> B: qpfid0 identity derivation
  -> C: identity <-> existing Level 0/evidence_binding/qpfpkg0
  -> D: identity verification integration
```

A, B, and C are landed on `main`. D is a future separately authorized implementation gate.

No economic implementation is implied by completion of D.

## 7. Public-claim constraints

Public materials must not claim or imply any of the following unless separately established, verified, and explicitly authorized:

- a fixed QPF economic percentage;
- guaranteed agent income;
- guaranteed economic value from verification;
- automatic QPF revenue from every agent;
- token-holder revenue entitlement;
- agents as financial assets;
- live economic activation when the corresponding rails are not operational;
- historical Pi royalties or CatalystPool arrangements as current QPF economics;
- historical Genesis, DEX, Railway, or Vercel infrastructure as the current canonical production state.

The long-term economic model must be described as roadmap/not-live until operational evidence exists.

## 8. Canonical production and repository posture

- `Quantum-pi-forge` is the canonical QPF hub.
- OINIO repositories are supporting agent/soul infrastructure.
- INFT agent/contract repositories are supporting or experimental until their claims and activation state are independently verified and authorized.
- Historical/superseded sites and Genesis infrastructure are not canonical production surfaces.
- The canonical production surface is the current QPF production deployment; historical deployment claims must not be presented as current merely because documentation remains in a satellite repository.

Repository lifecycle classification is a separate cleanup activity and is not authorized by this document.

## 9. AI and ecosystem strategy

The preferred partnership sequence is:

1. complete the QPF trust substrate;
2. demonstrate a smallest verifiable AI agent using existing QPF machinery;
3. pursue 0G as the first primary ecosystem partnership target around independently verifiable AI agents;
4. pursue model-provider and agent-framework integrations using a model-neutral verification proposition.

A partnership is not an authorization to alter QPF verification semantics, activate economics, or deploy new infrastructure.

## 10. Explicitly undecided / parked

The following are not decided by this strategy artifact:

- the percentage or rate of any future protocol participation;
- which economic event generates a share;
- who is the contractual payer;
- protocol-enforced versus contractual economics;
- token utility or token-holder economics;
- INFT settlement mechanics;
- regulatory classification of agent revenue or protocol participation;
- mint, liquidity, staking, Genesis, wallet, or other economic activation;
- `qpf.lineage.v1` as a new composition engine;
- BLAKE3 migration of the implemented identity-ID path.

## 11. Governance rule

This document is a strategy and policy reference, not an execution authorization. Every implementation, merge, deployment, economic action, repository lifecycle change, or external partnership action remains separately human-gated.

**Canonical principle:**

> QPF does not sell trust. QPF builds the trust layer and participates, later and only through explicitly defined mechanisms, in the economy that verified infrastructure enables.
