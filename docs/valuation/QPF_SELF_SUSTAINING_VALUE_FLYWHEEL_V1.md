# QPF Self-Sustaining Value Flywheel v1

Status: EVIDENCE_ONLY_FLYWHEEL_MODEL  
Created: 2026-07-04  
Audience: Founders, partners, grant reviewers, auditors, builders, strategic diligence reviewers

## Core thesis

QPF becomes self-sustaining by converting **verified infrastructure** into **trust**, trust into **participation**, participation into **usage**, usage into **revenue or funding**, and revenue/funding back into **audits, infrastructure, contributors, and public-good expansion**.

This is an **economic engine with brakes, receipts, and governance gates** — not a token-first launch strategy.

**Value must compound without sacrificing sovereignty.**

## The flywheel

```text
Evidence receipts
   ↓
Reviewer confidence
   ↓
Partner / auditor / grant readiness
   ↓
External validation
   ↓
More users / builders
   ↓
More measurable activity
   ↓
Higher defensible FMV
   ↓
More resources for audit, infra, travel, nodes, tooling
   ↓
Stronger QPF ecosystem
   ↓
(more evidence receipts)
```

Each turn of the flywheel should produce **new receipts**, not new hype.

## Seven compounding layers

Every valuation artifact should strengthen at least one layer:

| Layer | What it means for QPF |
|-------|----------------------|
| 1. Provable | Claims are backed by receipts, hashes, verifiers, and reproducible checks |
| 2. Auditable | Independent reviewers can scope contracts, permissions, and gates quickly |
| 3. Usable | Builders and operators can deploy, verify, and participate without guesswork |
| 4. Understandable | Partners and grants can grasp posture in minutes, not weeks |
| 5. Licensable | Modules can be packaged without selling Guardian authority |
| 6. Safe to participate in | Financial surfaces stay gated until authorization receipts say otherwise |
| 7. Hard to dismiss | Evidence density lowers the “interesting prototype” discount |

The sealed valuation lane (#562–#568) advances layers 1–4 and 7. This flywheel defines how layers 5–6 compound **without** reckless activation.

## Artifact test (every next deliverable)

| Question | Value effect |
|----------|--------------|
| Can an auditor verify it faster? | Lowers risk |
| Can a partner understand it faster? | Raises deal potential |
| Can a builder use it faster? | Raises adoption |
| Can a participant trust it faster? | Raises network effect |
| Can the system earn without speculation? | Raises sustainability |
| Can receipts prove no reckless activation happened? | Protects legitimacy |

If a proposed artifact fails this test, it is probably **noise**, not flywheel fuel.

## Value entry paths (sovereignty-safe order)

Revenue and funding should enter through paths that **do not require** premature mint, liquidity, staking, or bridge activation.

| Path | Sovereignty risk | Flywheel effect | Stage |
|------|------------------|-----------------|-------|
| Audit-readiness consulting | Low | Trust + auditor pipeline | Now |
| Deployment / license templates | Low | Licensable modules | Now |
| Grant funding | Low | Non-dilutive capital | Now |
| Enterprise / local AI verification packages | Low–medium | Partner revenue | Near |
| Stewardship services (setup, training, integration) | Low | Recurring services | Near |
| Controlled mint (after gates) | Medium | Ecosystem proof | Later |
| Participant growth + onboarding | Medium | Network metrics | Later |
| Staking / liquidity / bridge | High | Only after audit + authorization | Much later |

**Rule:** flywheel speed is limited by **proof density**, not activation appetite.

## Reinvestment loop

When value enters (revenue, grants, licensing, services), reinvestment should prioritize:

1. **Independent security audit** — largest FMV and trust unlock
2. **Infrastructure** — nodes, tooling, CI, verification harnesses
3. **Contributors** — builders who extend receipts and public-good surfaces
4. **Public-good expansion** — onboarding, education, open-core proofs
5. **Travel / field operations** — partner pilots, workshops, node deployment (when authorized)
6. **Controlled activation prep** — only with explicit governance receipts

Reinvestment without receipts is **spend**, not **compounding**.

## Non-transferable sovereignty (flywheel guardrail)

| May compound value | Does not transfer cleanly |
|--------------------|---------------------------|
| Code, docs, deployment patterns | Guardian authority |
| Receipts, verifiers, audit packages | Sovereign legitimacy |
| Tooling, templates, training | Human-rooted execution truth |
| Licensed modules | Un-gated financial activation |

> The implementation may be licensed. The sovereign authority is not for sale.

## What this model does not authorize

- Wallet action, signing, or broadcast
- Mint, liquidity, staking, or bridge activation
- Token speculation as the primary value strategy
- External FMV claims without appraisal, audit, or proof-of-use
- Transfer of Guardian authority as part of a licensing or partnership deal
