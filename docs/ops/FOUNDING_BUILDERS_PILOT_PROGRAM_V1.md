# Founding Builders Pilot Program v1

**Program name:** OINIO / Quantum Pi Forge — Founding Builders Pilot  
**Goal:** **10 builders** who genuinely use the system and say what works  
**Not the goal:** thousands of users, launch hype, token marketing  
**Engineering:** System ready — frozen except pilot-blocking fixes  
**Acquisition model:** Engineering-style feedback loop (not sporadic promotion)  

```text
E) Build a pilot program.

Collaboration frame (always):
  "I'm building this to solve X. I'd like feedback from people already
   working in this ecosystem. If it doesn't solve your problem, I'd like
   to know why."

Not:
  "Look at my project."
```

## 1. Who it’s for (10 seats)

| Seat type | Examples |
| --- | --- |
| **0G developers** | Building on 0G; agents, compute, data, infra |
| **Pi ecosystem builders** | App devs, utility creators — not casual tourists |
| **Local AI / OSS developers** | Ollama, Aider, Continue, MCP, coding agents |

**Fit test:** They have a workflow pain this week and would notice if a useful tool disappeared.

**Not fit:** Architecture tourists, investment seekers, “promote my bag” requests.

---

## 2. What founding builders get

| Get | Detail |
| --- | --- |
| Guided access | 15–30 min private AI operator / verify path (E1) |
| Direct line | Feedback heard by the maintainer |
| Influence | Repeated pains become the next product priority |
| Proof language | Optional co-signed or quoted receipt (with permission) |
| No paywall for pilot | No mint, no token buy-in, no wallet required |

---

## 3. What we ask for (feedback contract)

1. Try **one** real task from their work.  
2. Report: before time · after · friction · would use again.  
3. Answer: if it doesn’t help, **why**.  
4. Optional: allow a public quote / GitHub Discussion comment.  

```text
Their job is not to praise the stack.
Their job is to tell the truth about utility.
```

## 5. User acquisition system (repeatable loop)

Treat growth like debugging:

```text
1. Maintain list of communities + contacts (private)
2. Produce one high-quality post per target community
3. Track who responds
4. Record what people ask for
5. Prioritize product/docs from repeated feedback
6. Follow up after they try the project
7. Seal evidence receipts when use is real
```

### Weekly metrics (measurable)

| Metric | Target |
| --- | --- |
| Discovery conversations (Pi / 0G / AI-dev) | 5 + 5 + 5 (see weekly cadence) |
| Pilot page visits → reply | Track qualitatively |
| Builders who completed one task | cumulative toward 10 |
| Sealed external receipts | ≥1 ASAP, then 3–5 |
| Repeated pain themes | name top 1–3 |
| Feature/docs changes from feedback only | list |

### Private tracker (do not commit PII)

| # | Builder code | Track | Source | Status | Pain | Would use again? | Receipt? |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1–10 | | Pi/0G/AI | page/GH/DM | invited/active/done | | | |

**Status values:** invited · replied · session done · receipt sealed · churned · not a fit.

## 6. Why spend 15 minutes? (program answer)

```text
In 15 minutes you try one real builder workflow with a private AI operator
under your control. You leave knowing whether it saved time on a task you
already have — or why it didn't. No wallet. No hype. Honest feedback welcome.
```
