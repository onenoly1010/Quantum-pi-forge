## Adoption proof ladder (milestones)

| Proof | Definition | Evidence artifact | Status |
| --- | --- | --- | --- |
| **#1** | One developer completes a task and provides feedback | External receipt + optional GitHub issue | ⬜ pending |
| **#2** | That same developer comes back a second time | Second session log or receipt addendum | ⬜ pending |
| **#3** | A second independent developer joins | Receipt from different person | ⬜ pending |
| **#4** | Someone recommends the project unprompted | Note + permission to quote if public | ⬜ pending |
| **#5** | Someone builds something you didn’t anticipate | Description + link if public | ⬜ pending |

```text
Each milestone is evidence that the project creates value.
Not followers. Not a single announcement.
```

Update the Status column only when real outside evidence exists. Never invent rows.

## How to advance a proof level

1. Builder completes path (E1 / one task).  
2. Capture receipt (template).  
3. File feedback issue if public-safe.  
4. Update roadmap “from feedback” row if a change ships.  
5. Add redacted card to wall of receipts (with permission).  
6. Bump ladder status in this file only with evidence links.  

```text
ENGINEERING: system ready (frozen)
ADOPTION: verify with proofs #1–#5
LOCKS: held
```
