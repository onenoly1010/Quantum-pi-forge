## What QPF is (two sentences)

**Technical:**  
QPF turns technical claims into inspectable evidence.

**Human (the one people wake up with):**  
I need to know if this is real. I need to trust this before I risk money, time, or reputation. I need proof I can show someone else. I need a way to tell truth from claims.

**Honest one-liner:**

> QPF is a system designed to help people distinguish what is claimed from what can be demonstrated. Its purpose is to restore trust where uncertainty exists.

Now the world answers whether that matters.  
Not the end. **The first external measurement.**

## The test (extremely small)

### What the person receives

1. **A specific claim or problem** they already care about  
   (their deploy, their project, or a concrete public claim — not a tour of QPF)  
2. **A QPF verification output**  
   (short report / certificate-style artifact: checked / gated / not checked)  
3. **One question:**

> Did this make a decision easier, safer, or more trustworthy?

### Their answer becomes Certificate #001

Not a marketing testimonial. **Evidence.**

```text
Certificate #001 (human usefulness form)

Person: external (not builder core loop)
Claim / problem they brought:
What they were shown / given:
Answer to the question (verbatim if possible):
  Did this make a decision easier, safer, or more trustworthy?
  YES / NO / PARTIALLY
  Because: ______

Optional:
  Would use again? YES / NO / MAYBE
  Want formal certificate later? YES / NO
  Pay someday? YES / NO / MAYBE

Timestamp (UTC):
No interpretation beyond recording their words.
```

That is the first certificate the system **cannot invent** without lying.

## Sequence

```text
1. Keep locks held
2. Optional: merge/deploy only to make the surface usable
3. One person with a real trust problem
4. One claim + one verification output
5. Ask the one question
6. Record their answer as Certificate #001 (human usefulness)
7. Only then: adapt — from their words, not from architecture appetite
```
