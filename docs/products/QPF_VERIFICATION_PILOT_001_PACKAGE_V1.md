## Pilot definition (bounded)

```text
QPF Verification Pilot #001

Purpose:
  Determine whether a third party can understand and use a
  bounded verification output.

Participant:
  1 external human/entity (not builder core loop).

Input:
  One defined technical claim or artifact.

Output:
  Verification report:
  - evidence reviewed
  - verification method
  - confidence level
  - unknowns
  - limitations

Success condition:
  Participant states the output helped them make a decision
  (easier, safer, or more trustworthy — or fills "because ______").

Failure condition:
  Participant cannot derive value or the output is unclear.

Explicitly out of scope:
  No token, liquidity, investment, or ecosystem claims.
```

## Package contents (internal prepare)

### 1. Pilot offer (what we say we will do)

| Element | Definition |
| --- | --- |
| Name | QPF Verification Pilot #001 |
| Promise | Bounded verification of **one** claim/artifact; honest labels |
| Delivery | Short report + optional certificate-format artifact |
| Timebox | One engagement; no open-ended retainer unless later GO |
| Price for this pilot | **Free for feedback** preferred · or founder $250–500 CAD if both prefer paid |
| Ask of participant | Honest answer to the success question |

### 2. Evidence artifact (what they receive)

Must include:

| Section | Required |
| --- | --- |
| Evidence reviewed | Yes |
| Verification method | Yes (e.g. RPC, explorer, docs vs state) |
| Confidence level | Yes (high / medium / low / unknown) |
| Unknowns | Yes |
| Limitations | Yes (roadmap, value, adoption, audit guarantees — not claimed) |
| Result labels | verified / partial / gated / not verified / unknown |

Template: `examples/QPF_VERIFICATION_CERTIFICATE_001_TEMPLATE.md`  
Internal process demo: `#000` (self — not external #001)

### 3. Acceptance criteria (success / failure)

| Outcome | Criteria |
| --- | --- |
| **Success** | External participant says the output **helped them make a decision** (or “helped because ______”) |
| **Failure** | Cannot derive value **or** output is unclear to them |
| **Partial** | Some value, but material confusion remains — record and revise |

Also capture the five questions from the commercial gate (request? process fit? understood? reduced uncertainty? recommend/pay?).

### 4. Explicitly **not** included

| Out of scope |
| --- |
| Formal security audit guarantee |
| Token value / investment advice |
| Liquidity, mint, staking, “economy is live” |
| Full OINIO vision onboarding |
| Unlimited support or rewrites of their product |
| Claims of adoption or market validation of QPF |
